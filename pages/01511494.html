Renaming Electrical Engineering Terms

· archived # 1,511,494
I come from a computer programming background. In computer programming using good names is one of the most important things in coding. Naming is the one of the most fascinating parts of computer programming and is directly applicable to real world. For example lets say you want to convert a word document into html, and then post it to your website programmically. You’d create a function in a coding language and the function would have a name. A bad name would be something like ‘processdata’ or ‘senddata’, if you were to reread that code 2-3 months from now, you’d have no fricken clue what you meant by ‘processdata’ or ‘senddata’. If someone else reads that code, they'd have no fricken clue what you meant by 'processdata' or 'senddata'. Those names are incredibly vague and could quite literally mean almost anything. This means you(or the person reading your code) would have to physically look through the code of the function to figure out and understand what it does. This can take anywhere from a few minutes to a few days depending on complexity. If you instead named the function ‘postdoc2htmlwebsite’ or ‘convertdoc2htmlpost’ then if you reread that code 2-3months from now, you’d know exactly what it does, no understanding of the underlying code is required, and you save minutes/hours/days of your time. My point is good names can allow for the complete bypass of memorization. You can extend this into other subjects to completely bypass memorization of the terms within the subject. The names used in electrical engineering are horribly named. Names like ‘Ohm’, ‘Weber’, ‘Volts’, ‘Amps’, ‘Newtons’, ‘Joules’, ‘Columbs’ etc are named after whomever ‘discovered’ the equation for the relationship. Because electrical engineering terms are so badly named we have to physically figure out what's actually occurring in reality and spend brain memory space to associate the bad name to the actual concept.
