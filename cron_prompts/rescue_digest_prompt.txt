Run the RESCUE DIGEST on the cloud sandbox. This is the connective-tissue job: it folds
the week's rescues, the at-risk queue, and the archive's structural gaps into ONE digest
that lands as an input for the synthesis layer BEFORE Forge writes his weekly report.
Purpose: the synthesis should see the rare and at-risk material, not have it buried
under the bulk scout feed.
The sandbox may have been RESET; bootstrap from GitHub FIRST.

1) BOOTSTRAP
   if /root/workspace/AFLinks/.git does not exist:
     git clone --filter=blob:none --sparse --depth 1 https://github.com/Focusingpulse/AFLinks.git /root/workspace/AFLinks
     cd /root/workspace/AFLinks && git sparse-checkout set database forge index_shards cron_prompts scout
   cd /root/workspace/AFLinks && git pull --rebase --quiet origin main

2) FAMILY GATE (skip cleanly when the tooling isn't attached)
   GATE="$MEMORY_DIR/../cron-coordination/family.py"
   if [ -f "$GATE" ]; then
     python3 "$GATE" run-gate --member rescue-digest || { echo "rescue-digest: skipped (family budget low)"; exit 0; }
   else
     echo "note: cron-coordination shared memory not attached to this agent — family gate skipped"
   fi


3) GATHER THE WEEK (last 7 days)
   a. What the rescue-sweep brought in: new index_shards entries with archive_ts /
      provenance in the last 7 days, via `git log --since` on index_shards/ and by
      reading the entries' own timestamps.
   b. What endangered-prospect queued: rescue/queue.json targets, highest score.
   c. What curation-pass flagged: rescue/repair-queue.json.
   d. Structural gaps — the FAL pass. What is the archive THIN on? Compare
      taxonomy_counts.json against the meta-category list and name the emptiest
      corridors. Say which tradition or geography is under-covered.

4) WRITE THE DIGEST
   Path: forge/synthesis/inputs/<YYYY-MM-DD>-rescue-digest.md
   Frontmatter: name + description (required by the repo memory contract).
   Sections:
     - Rarest rescues this week (title, provenance, why it matters)
     - Most at-risk still out there (from the prospect queue)
     - What the archive is thin on (the gap list)
     - Suggested next-week corridors (concrete: domains, languages, collections)
   Keep it SHORT and dense. This is an input to someone else's synthesis, not a
   synthesis itself. No filler, no restating the whole archive.

5) COMMIT — READ CAREFULLY
   `git push` DOES NOT WORK for this repo (AFLinks is ~3.9 GB; push fails with
   HTTP 500 / send-pack disconnect — a transfer failure, not a permission one).
   Write through the API instead:
     python3 - <<'EOF'
     import json
     json.dump({
       "forge/synthesis/inputs/<date>-rescue-digest.md": {"file": "forge/synthesis/inputs/<date>-rescue-digest.md"},
     }, open("/tmp/changes.json","w"))
     EOF
     GUTHUBN="$GUTHUBN" python3 aflinks_api.py put --manifest /tmp/changes.json \
       --message "rescue-digest: week of <date>"

6) CHECK IN
   [ -f "$MEMORY_DIR/../cron-coordination/family.py" ] && python3 $MEMORY_DIR/../cron-coordination/family.py check-in --member rescue-digest \
     --status ok --summary "rescue digest <date>: <n> rescues, <n> at-risk, <n> gaps"

7) REPORT ONE LINE: digest path, rare-find count, biggest gap named.
