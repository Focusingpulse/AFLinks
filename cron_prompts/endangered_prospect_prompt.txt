Run ENDANGERED PROSPECT on the cloud sandbox. This is the FORWARD-LOOKING half of the
rescue lane: find material at risk of disappearing BEFORE it goes, and hand the sweep a
ranked target queue. It does not download documents — it finds them and ranks them.
The sandbox may have been RESET; bootstrap from GitHub FIRST.

1) BOOTSTRAP
   if /root/workspace/AFLinks/.git does not exist:
     git clone --filter=blob:none --sparse --depth 1 https://github.com/Focusingpulse/AFLinks.git /root/workspace/AFLinks
     cd /root/workspace/AFLinks && git sparse-checkout set database forge index_shards cron_prompts scout
   cd /root/workspace/AFLinks && git pull --rebase --quiet origin main

2) FAMILY GATE
   python3 $MEMORY_DIR/../cron-coordination/family.py run-gate --member endangered-prospect
   Non-zero (budget LOW) => no work, no writes; say "endangered-prospect skipped
   (family budget low)" and stop. Unknown member => register or proceed (advisory).

3) LANGUAGE ROTATION
   Read rescue/rotation.json for the last language used, then advance:
   ru -> fr -> de -> it -> es -> zh -> ja -> uk -> pt -> ru
   Save the new value back in the same file. This keeps prospect fires from
   re-hunting the same corridor and turning up the same domains.

4) HUNT — look for at-risk material NOT already in the archive.
   Work by DOMAIN CORPUS, not single URLs: a whole vanishing site can be
   reconstructed from CDX, but a single dead link is almost worthless.
   Risk signals, strongest first:
     - registrar expiry / domain parked / "for sale" page
     - no HTTPS, or an expired certificate
     - stale "last updated" (years old) on a still-live page
     - single-maintainer hosting (personal site, one author's name on everything)
     - ZERO existing Wayback coverage  <-- highest value, nothing else holds a copy
     - forum-only or mailing-list-only hosting
     - defunct society / one-off conference sites, retired university repositories
   Useful checks:
     curl -sS -o /dev/null -w '%{http_code}' --max-time 15 <url>
     curl -sS "http://web.archive.org/cdx/search/cdx?url=<domain>&matchType=domain&output=json&collapse=digest&fl=timestamp,original&limit=5"
   A domain with live content but NO CDX rows is the highest-priority rescue target
   in the entire lane: if it goes, nothing anywhere holds a copy.

5) SCORE AND RANK
   Rank by: no archive coverage > expires soon > single maintainer > stale > other.
   Prefer depth over breadth — five genuinely rare finds beat fifty routine ones.

6) WRITE THE QUEUE
   Merge (do not overwrite) into rescue/queue.json. Schema:
     {"generated_at": "<iso>", "targets": [
        {"domain": "...", "why": "...", "risk": "no-archive|expiring|stale|...",
         "score": 1-10, "found_via": "<lang corridor>", "checked": "<iso>"}]}
   Keep existing targets; update their scores rather than duplicating them.
   Also append newly discovered dead/expiring domains to site_queue.json so the
   daily sweep can pick them up directly.

7) COMMIT — READ CAREFULLY
   `git push` DOES NOT WORK for this repo (AFLinks is ~3.9 GB; push fails with
   HTTP 500 / send-pack disconnect — a transfer failure, not a permission one).
   Write through the API instead:
     python3 - <<'EOF'
     import json
     json.dump({
       "rescue/queue.json":   {"file": "rescue/queue.json"},
       "rescue/rotation.json":{"file": "rescue/rotation.json"},
       "site_queue.json":          {"file": "site_queue.json"},
     }, open("/tmp/changes.json", "w"))
     EOF
     GUTHUBN="$GUTHUBN" python3 aflinks_api.py put --manifest /tmp/changes.json \
       --message "endangered-prospect: +<n> targets (<lang> corridor)"

8) CHECK IN
   python3 $MEMORY_DIR/../cron-coordination/family.py check-in --member endangered-prospect \
     --status ok --summary "prospect: +<n> targets, <lang> corridor"

9) REPORT ONE LINE: targets added, highest-risk find, language corridor used.
